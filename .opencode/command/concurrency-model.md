加载 `concurrency-modeling` 技能，对 **$ARGUMENTS** 执行并发建模：

1. **先问值得吗**：动的是共享生命周期状态吗？错了会静默难复现吗？爆炸半径大吗？**不满足就直说不值得**——建议普通测试 + 评审，或输出「非目标」声明并停止，不要硬套流程。
2. 按 **①–⑦** 顺序分析，每步给推理链。【人定】项（契约、所有权、不变量、豁免）给候选 + 倾向 + 理由，留人确认。
3. 产出 `notes/Invariants/<组件>.md`，严格用 `references/template.md` 骨架，**一屏内、表格优先**（主体：契约 / 不变量+检测器 / 豁免）。
4. 对话内给浓缩版：**先「人话版」（是什么 / 会出什么事 / 要决定什么），再上术语**；末尾附待确认问题清单（实质项逐条问，记账项批量确认）。
5. 以「请确认或要求修改」结束。**不进入实现，不写代码。**
