# ①–⑦ 检查清单

> 顺序即分析顺序，每一步都要有推理链，禁止直接甩结论表格。
> 标 **【人定】** 的项必须由人确认；标 **【AI】** 的可由 AI 起草，但需人过目。

## ① 定义系统行为 【人定】

> 人话：这个类答应怎么用、不答应什么。

先于一切。不定义"应该怎样"，后面所有不变量都没有基准。

- 目的 / 契约（前置 · 行为 · 返回 · 副作用）/ 生命周期 / 正常异常流 / 调用方义务。
- 关键问：返回的引用/句柄**有没有租约，还是裸借用**？（人话：东西借出去后，别人把它销毁了算谁的责任？）谁负责"使用期"？
- 系统在并发下**必须保持不变**的行为是哪些？
- 产出：契约表 + "不承诺/非目标"声明。

## ② 识别共享资源 【AI 枚举，人确认】

> 人话：哪些东西会被多条线程同时碰。

从①倒推：哪些状态被多个执行流访问且需一致？

- 分类：可变状态 / 非线程安全外部对象 / OS 句柄 / 队列 / 持久化状态 / 逻辑资源。
- 找出**复合操作（check-then-act）**——头号缺陷形状。
- 产出：共享资源表 + check-then-act 点清单。

## ③ 定义并发边界 【AI 主导】

> 人话：到底哪些线程会同时来、在哪儿撞上。

对每个操作列出**所有到达路径**，再判断哪些真会时间重叠。

- 上下文：采集定时器 / 请求线程 / 协议回调 / 后台服务 / 健康监控 / 关停 / 取消。
- 重点抓**因果相关但线程分离**：A 触发事件 → 另一线程回调 → 动 A 刚用的资源（如 fire-and-forget 健康回调）。
- 产出：到达路径表（路径 × 是否重叠 × 证据）。

## ④ 定义所有权 【人定】

> 人话：谁、在什么时候、有权销毁它。

- 独占/共享、粒度、**生命周期 vs 使用期**、唯一访问入口。
- 标出**借出处的所有权断裂**，分析加租约的成本 vs 接受边界。
- 产出：所有权表（资源 × 归属 × 释放时机 × 入口）。

## ⑤ 定义不变量 / 状态转换 【人定 + AI】

> 人话：无论怎么并发都必须**永远成立**的事实。

- 状态机三件套：状态集 / 允许迁移 / 终态。
- 四类不变式：状态 / 迁移 / 终态 / 进展。
- 每条要有**违反检测器**（否则无法裁判）。
- 显式写出**不承诺的边界（豁免）**，每条带理由 + 风险注记——往往比不变量更重要。
- 产出：不变量表（不变量 | 检测器 | 豁免）。

## ⑥ 定义同步规则 【半自动】

> 人话：加锁的范围——哪些操作必须锁住、哪些放出锁外。

互斥 / 锁序 / 可见性 / 取消传播 / 顺序阻塞策略。

- 写清哪些动作留临界区（保原子）、哪些移锁外（慢 I/O），及理由。
- 异常路径：临界区内抛异常是否释放？取消如何传播？
- 产出：同步规则 + 临界区边界图。

## ⑦ 选择实现机制 【AI】

> 人话：用哪种写法（`lock` / `Channel` / 原语…）。

`lock` / `Interlocked` / `SemaphoreSlim` / `Channel` / `Lazy` / 不可变快照 / Actor。

- 给 **2–3 个候选**，每个写出**会在什么时序下失败**。
- 优先**结构强制**而非"约定+自觉"：新增方法时"想绕都绕不过"才算数。
- 人选一个后，记录选择理由与被拒候选（供未来回溯）。
- 产出：机制对比表 + 选定 + 理由。
