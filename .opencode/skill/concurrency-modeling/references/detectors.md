# 检测器与攻击测试

> 核心原则：**测试无法证明"没有竞态"，只能证明"没发现"。** 所以每条检测器必须先证明自己**有能力失败**。
> 人话：检测器 = 一个能把"不变量被违反"抓出来的测试；没有它的不变量就是空话。

## 一、负控（负控不过 = 假绿）

> 人话：负控 = 把代码故意改坏（seeded fault），看测试是否**真变红**；不变红说明这测试永远绿、根本没在检查（假绿）。

每条检测器都要拿一个**故意写坏的参考实现（seeded fault）**验证：坏实现上它**必须变红**。

- 做不红 → 检测器无效，报告"该检测器无法证伪"，重做。
- 只写正例（真实现上绿）不算数——永远绿的测试毫无价值。
- **必须可执行**：负控只能是下面两种载体之一，且进 CI。**在注释里写"把 X 改成 Y 应红"不算数**——那是手工步骤，会腐烂、拦不住回归。
  - (a) **测试内坏参考实现**：接口可做 `Broken*` 类，配同一断言 helper；好实现绿、坏实现红。首选。
  - (b) **测试 seam**：生产代码 `InternalsVisibleTo` / 注入钩子，仅当算法无法在测试侧复制时用。

## 二、受控交错（禁用随机 sleep 碰运气）

> 人话：用 `Barrier`/信号量等**确定性地**逼出并发顺序，而不是随机 `sleep` 碰运气。

不要写 `Task.Delay(随机)` 然后祈祷。用**确定性手段**逼出交错：

| 手段 | 用途 |
|---|---|
| `Barrier` / `CountdownEvent` | 让 N 个执行流同时到达某点再放行 |
| `TaskCompletionSource` | 卡住加载/回调，制造"并发都错过快路径"的窗口 |
| 注入延迟委托 / 钩子 | 在临界区前后插入可控停顿 |
| 单线程确定性调度 | 串行复现同一交错（可重复） |
| 竞态检测器 | 系统化探测数据竞争（工具辅助，非 AI 判断） |

## 三、攻击测试契约（Adversary 遵守）

- **输入只给**：不变量表 + 检测器预期 + 对外 API + 坏实现。**不给实现内部推理/注释**（盲测）。
- 每条不变量至少一条攻击测试：
  1. 坏实现上**必须红**（负控）；
  2. 真实现上预期绿；
  3. 用受控交错，禁止随机 `sleep`。
- **输出**：命令、原始输出、期望 vs 实际、每条不变量状态；发现反例给**最小复现**。
- **禁止**：改 src、改不变量、删/弱化检测器。只报告。
- 盲测后再跑一轮**白盒**补漏（看实现找弱点），但顺序必须是 blind → white。

## 四、检测器必须覆盖的并发类别

逐项确认是否适用，不适用写豁免：
取消传播 · 关停/排空顺序 · 释放/Dispose 生命周期 · 重入 · 临界区内异常是否释放 ·
fire-and-forget 回调 · 锁序/死锁 · 内存可见性 · 定时器重入 · async void ·
SynchronizationContext 捕获 · check-then-act。

## 五、.NET 常用断言形状（示例）

- 单飞：N 个并发 `GetOrLoad`，断言工厂调用次数 == 1（见 `TtlCacheTests`）。
- 取消不重试：取消后断言尝试次数 == 1。
- 排空：关停时断言队列耗尽且无丢件。
- 不变量守护：并发下断言状态集合始终属于允许集。

## 六、退出

检测器全绿 + 每条过负控 + 未探索交错空间已记录 + 无新反例 = 可退出。
