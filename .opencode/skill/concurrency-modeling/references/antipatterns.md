# 并发反模式与非目标

## 一、头号反模式

| 反模式 | 人话 | 症状 | 对策 |
|---|---|---|---|
| check-then-act | "先判断、再操作"，两步之间状态被别人改了 | "先判断再操作"两步之间状态被改 | 闸门+双检 / 原子原语 / 唯一入口 |
| 裸借用 | 东西借出去后没人管使用期，可能用着被销毁 | 返回内部可变引用，调用方无租约 | 加租约 / 不可变快照 / 明确使用期 |
| fire-and-forget | 丢出去就不管的后台调用，回头动了你刚用的东西 | 回调在别的线程动刚用的资源 | 显式所有权与取消传播 |
| 无锁英雄 | 手写无锁，还说不清什么时候会错 | 手写 CAS/无锁结构，说不清失败时序 | 默认用锁/Channel；无锁必须写失败分析 |
| 临界区塞慢 I/O | 锁里做网络/磁盘，把别人全卡住 | 锁内做网络/磁盘 | 慢 I/O 移锁外，只留原子部分 |
| 异常漏锁 | 临界区抛异常了，锁没释放 | 临界区抛异常未释放 | try/finally / 原语自带释放 |
| 定时器重入 | 上一轮没跑完，下一轮又进来了 | 上次未完成下次又触发 | 单飞 / 跳过重叠 / 闸门 |
| 关停竞态 | 停机时任务没排空、资源被提前销毁 | 停机时队列未排空/资源被提前释放 | 定义排空与释放顺序 |
| 注释式负控 | 把"如何把代码改坏"写在注释里，靠人手工验 | 注释写"认证方式"，无自动化；回归拦不住 | 负控做成可执行测试（seeded-fault / seam），进 CI |
| 假绿 | 测试永远通过、其实没在检查 | 正例常绿、坏实现上也绿 | 每条检测器必须过负控，否则标"无效" |

## 二、禁止清单（硬条款）

1. 禁止"列多种写法却不收敛到 1 个"。
2. 禁止无锁实现而不写失败分析。
3. 禁止自称"线程安全"——必须由检测器证明。
4. 禁止弱化/删除检测器来变绿（等同模型变更）。
5. 禁止把难啃时序塞进"豁免"当垃圾桶——每条豁免需理由 + 风险。
6. 禁止注释式负控——负控必须可执行（见 `detectors.md`）。

## 三、明确不统一（语义不同，强行合并会错）

来源：`notes/Todo/MechanismUnification/README.md` C 节。

- **熔断（门控）vs 设备健康判定 vs 连接生命周期**：状态集与迁移语义不同，只可抽底层原语，不合并状态机。
- **告警 Duration 去抖 vs 值管道死区/降频**：看"持续时长" vs 看"变化幅度/采样率"，时间语义不同。
- **命令幂等 vs 告警去重**：一个必须跨重启，一个只在活动期去重。
- **DB outbox vs 内存队列**：耐久性要求不同，是两类东西。

## 四、范围门槛（防止官僚化）

- 只对**有共享生命周期资源**的子系统启用。
- 无共享状态 → 显式写非目标后退出，不套全流程。
- 差异能用**参数/策略**表达 → 复用机制层原语；差异是**领域语义** → 单独建模，不合并。
