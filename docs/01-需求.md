# 01 需求文档（NitroGateway）

> 版本：v1.0 ｜ 日期：2026-08-30 ｜ 依据：仓库现状（代码 + notes/ADR + FACTORY-TEST.md）

## 1. 背景与问题

NitroGateway 是运行在工控机或边缘盒子上的**工业物联网边缘网关**，解决「现场 PLC 数据如何稳定、安全、低成本地上云」的问题。

现场普遍存在的痛点：

| 痛点 | 说明 |
| --- | --- |
| 协议碎片化 | PLC 厂商协议各异：Modbus TCP / RTU、Siemens S7、OPC UA，需要统一接入层 |
| 网络不可靠 | 现场网络抖动、断连、带宽有限，数据上行必须断网不丢数 |
| 无人值守 | 边缘盒子 7x24 运行，需自愈（熔断、重连、看门狗）与磁盘保护 |
| 数据量失控 | 1s 周期 x 多设备 x 多点位，全量上云流量与存储成本不可控，需抑制无效数据 |
| 运维黑盒 | 现场无法直接进机器，需远程可观测（指标/日志/追踪/健康检查） |
| 反向控制 | 云端要能下发写值命令（云 → 网关 → PLC），且带回执与幂等 |

## 2. 目标与非目标

### 2.1 目标

1. 统一采集：一套引擎接入 Modbus TCP/RTU、S7、OPC UA，设备/点位配置化，运行期热加载。
2. 本地时序存储：采集数据先落本地 SQLite，断网不丢；带保留策略与磁盘保护。
3. 可靠上行：MQTT（QoS1）转发，两阶段提交 + 重试 + 死信，断网恢复自动续传。
4. 实时可视化：Vue 3 管理面板 + SignalR 实时监控、历史曲线、告警、系统状态。
5. 云端告警：阈值规则 + Duration 去抖 + 生命周期管理 + MQTT 通知（可插拔）。
6. 命令回写闭环：订阅云端命令 → 写 PLC → 回执，幂等去重。
7. 可观测：Prometheus 指标 + Serilog 结构化日志 + OpenTelemetry 追踪 + 健康检查。
8. 安全：JWT + RBAC + 写值门控（WriteGuard）+ 审计日志。

### 2.2 非目标（明确不做，硬边界）

- 不做云端大数据分析/BI（那是中心/云端平台职责）。
- 不做设备固件升级、远程桌面等边缘管理平台功能。
- 不做全量 Identity 用户体系（用轻量 users 表 + 管理接口，见 ADR-066）。
- 多现场「中心」形态暂不落地为独立产品（ADR-054：web 收敛为纯边缘；中心如需要另立项目）。
- OPC UA 的 Browse 节点树、证书互认暂不实现（ADR-060 诚实边界）。

## 3. 用户与角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| Admin | 管理员 | 设备/点位增删改、用户管理、配置修改、写操作、安全 |
| Operator | 操作员 | 查看状态、确认告警、导入点位、写操作（需 WriteGuard 校验） |
| Viewer | 观察者 | 只读仪表盘与历史数据 |

## 4. 功能需求

### 4.1 设备与点位管理

- 设备 CRUD：协议（Modbus TCP/RTU、S7、OPC UA）、Endpoint、UnitId、串口参数、站点归属（Site）。
- 点位 CRUD：地址（4xxxx/3xxxx/0xxxx/1xxxx 等）、数据类型（Bool/Int16/UInt16/Int32/UInt32/Int64/UInt64/Float/Double/String）、工程缩放、死区、ScanIntervalMs 降频、读写权限（ReadOnly/WriteOnly/ReadWrite）。
- CSV 批量导入/导出点位；批量生成点位（模板 + 地址递增）。
- 设备连接测试、单点位测试连接（区分误报，ADR-023）。
- 运行期配置热加载：当前周期不中断，下一周期自动切换（DeviceCache）。

### 4.2 采集（Collection）

- 周期采集：默认 1s 一轮，多设备并发 ≤ Collection:MaxConcurrency（默认 5）。
- 点位级降频：ScanIntervalMs 独立调度，死字段不必每秒读（ADR-062）。
- 值管道：类型转换、工程缩放（Scale/Offset）、死区变化抑制（ADR-053）。
- 每设备独立熔断器：连续 5 次失败 → Open（拒绝采集）→ 冷却 30s → HalfOpen 探测 → 成功回 Closed；冷却翻倍上限 5min。
- 健康监控：3 次连续失败 → Offline，3 次连续成功 → Online；初始 Unknown 自动转 Online。

### 4.3 本地存储（Persistence）

- SQLite（EF Core 元数据 + Dapper 批量写 + FluentMigrator 迁移）。
- 时序数据保留策略：默认 30 天自动清理。
- 磁盘保护：剩余空间 < 1GB 预警、< 256MB 降级暂停转发出队（ADR-012）。
- 数据库文件：nitrogateway.db（运行时文件，不提交）。

### 4.4 上行转发（Forwarder）

- MQTT 通道（默认）：nitrogateway/{siteId}/{deviceId}/measurements，QoS1，camelCase JSON。
- HTTP 通道（可选）：POST /api/measurements/batch（Forwarder:Channels = http/both）。
- 两阶段提交缓冲（Forward Outbox）：Pending → InFlight → Commit；失败 MarkFailed（retry+1）。
- retry ≥ 5 → 死信队列；Admin API 可查看/重放/丢弃。
- 断点续传：进程 kill 后 InFlight 退回 Pending 自动补发；停机前 drain 排空。
- 固定批量上限（单轮 1000 批 / 单轮排水 2000 批）限流，防 MQTT 恢复瞬间冲垮 Broker（2026-08-22 起以固定上限替代 AIMD，简化）。
- MQTT 转发总开关：运行期启停上云（ADR-059/061）。
- 上行载荷携带点位权限 access（0/1/2），云端可识别可写点（2026-08-29）。

### 4.5 告警（Alarm）

- 阈值规则：> >= < <= == != Between。
- Duration 去抖：值持续超限 N 秒才触发，中间回落重置计时。
- 生命周期：Pending → Active → Acknowledged → Resolved；Active 期间不重复告警。
- 通知：MQTT 推送（IAlarmNotifier 可插拔，钉钉/企微/邮件可扩展）。

### 4.6 命令回写（Command，ADR-069）

- 订阅 nitrogateway/+/+/commands（QoS1），载荷 {commandId, type:WritePoint, pointId, value, requestedAt}。
- 幂等：commandId 去重缓存，重复投递重发回执、不重复写值。
- 回执：nitrogateway/{siteId}/{deviceId}/commands/ack，{commandId, result: Success/Failure, error, at}。

### 4.7 实时与可视化（Web）

- 页面：登录、仪表盘、设备管理、点位管理、实时监控、历史曲线、告警、告警规则、死信、审计、系统状态、站点身份、用户管理。
- SignalR 实时推送（JWT 认证），实时监控页左选择 + 左数据 + 右曲线布局（2026-08-23）。

### 4.8 桌面端（Windows，WPF）

- 形态 2 的 Windows 边缘端：本机采集 + 本地库 + 本地 UI，MQTT 发布到配置的 broker。
- 设备/点位配置界面、告警规则管理、实时曲线、历史、设置（MQTT 地址可编辑 + 测试连接，DPAPI 密码）。
- 与 web 同一套引擎类库（Domain/Collection/Forwarder/Protocol 等复用）。

### 4.9 安全与审计

- JWT 认证、RBAC 授权（Admin/Operator/Viewer，5 个策略）。
- WriteGuard 三级门控：设备模式 + 值范围 + 变化率（FluentValidation）。
- 审计中间件：所有 /api/* 访问记录结构化日志。
- 登录限流（LoginRateLimiter）。
- 用户 DB 化 + 管理接口（ADR-066）；首启从配置种子灌入。

### 4.10 系统管理

- 健康检查：/healthz（存活）、/readyz（SQLite+MQTT，就绪）。
- 指标：/metrics（Prometheus）。
- 站点身份管理（Site:Id，app_meta 持久化）。
- 配置同步（outbox 边缘 → 中心，双向 UpdatedAt 合并，ADR-033；中心未配置时静默跳过）。

## 5. 非功能需求

| 维度 | 需求 |
| --- | --- |
| 可靠性 | 断网/断 broker 不丢数；进程 kill 可恢复；故障设备熔断隔离，不影响其它设备；7x24 无人值守 |
| 性能 | 10 台设备 x 50 点位 x 1s 周期并发采集；单机转发积压上限 100000 批；8h 长稳内存 ≤ 初始 2 倍 |
| 数据量 | 死区变化抑制 + 心跳兜底（300s），存储/MQTT/SignalR 共用放行子集（ADR-053 数据量杠杆） |
| 可用性 | Docker 一键部署、systemd 服务化 + 主机级看门狗（连续 3 次探测失败重启网关） |
| 安全 | 生产强制环境变量（JWT_SECRET / 三账号密码），未设置拒启；生产禁用默认测试账号 |
| 可观测 | 指标 + 结构化日志（7 天轮转）+ OTel 追踪（9 个 Span）+ 健康检查 |
| 存储 | SQLite 8h 增量 ≤ 50MB（10 点位 1s）；保留 30 天 |

## 6. 验收标准（出厂门禁，源自 FACTORY-TEST.md）

P0（必须全过）+ P1（必须全过）→ 判定「可用、可长期运行」：

| 场景 | 级别 | 要点 |
| --- | --- | --- |
| T0 构建 + 测试 + 启动 | P0 | build 0 错；单测 ≥782；集成 ≥51；前端构建 0 错；≤15s 启动就绪 |
| T1 单设备端到端 | P0 | 采集入库 + MQTT 转发 + 前端展示 |
| T2 多设备并发（10 设备） | P0 | 并发限流、故障隔离（关 3 台其余 7 台不受影响）、自动恢复 ≤35s |
| T3 8 小时长稳 | P0 | 内存/转发积压/SQLite 增长/日志轮转/数据连续/重启恢复 |
| T4 故障恢复 | P1 | 网络断、MQTT 断、进程 kill、配置热加载 |
| T5 安全与权限 | P1 | 401/403、审计齐全、SignalR 拒绝匿名 |
| T7 中心形态端到端 | P1 | 现场 → broker → ingest → 中心库 → 中心 Web（需中心栈） |

## 8. 约束

- 上行/下行 MQTT 契约以本仓库（网关侧）为准，云侧（NitroCloud）配套实现。
- 依赖版本不随意升降级（锁定 HslCommunication 12.9.2 等）。
- 库结构变更走 FluentMigrator 迁移；*.db 运行时文件不提交。
- Storage/、Protocol/Abstraction/ 为纯接口层，接口只增不删。
