# NitroGateway 写功能（控制下发）实现指南

> 面向对象：需要对照本指南自行实现“写（下发控制指令）”功能的后端 / Web / 桌面开发。
> 现状：**协议驱动层的写能力（WriteAsync / WriteBatchAsync）已经全部实现**，WriteGuard 门控与测试也已完成，缺的只是**业务接线**（写端点、写服务、UI、数据库 Min/Max 字段）。
> 本文档给出实现路径、代码骨架与可复用清单，可直接照做。

## 二、总体架构（写链路）

```
┌──────────┐   ┌──────────────────┐   ┌───────────────┐   ┌────────────────┐
│ Web 前端   │──▶│ POST /api/.../write │──▶│ IWriteService │──▶│ WriteGuard     │
│ Monitoring│   │ (Authorize)       │   │ (Device 模块) │   │ .Evaluate(cmd) │──校验失败→拒
└──────────┘   └──────────────────┘   └───────────────┘   └────────────────┘
                                                                  │ 通过
                                                                  ▼
┌──────────┐   ┌───────────────┐   ┌──────────────────────────────┐
│ 桌面 WPF   │──▶│ RealtimeVM    │──▶│ IProtocolDriverPool         │
│ 写按钮+弹窗 │   │ (直接走同链路) │   │ .GetOrCreate(device)        │
└──────────┘   └───────────────┘   └──────────────────────────────┘
                                              │
                                              ▼
                             ┌──────────────────────────────┐
                             │ driver.WriteAsync(point,val) │──▶ OperationResult
                             │ （Modbus/S7/OPC-UA 已实现）     │
                             └──────────────────────────────┘
                                              │
                                              ▼
                                       可选：写审计 / 写历史落库
```

核心原则：
- **写校验与写执行分层**：`WriteGuard` 只做校验，驱动只做写入，中间由 `WriteService` 串联。
- **写操作不走采集管道的 Polly 重试**：`ReliableProtocolDriver` 的 `WriteAsync` 是透传（注释明确“由上层控制重试”），写命令**默认单次执行**，避免重复写造成事故；重试策略由写服务自行决策。

## 三、后台实现

### 3.1 数据库改动（FluentMigrator 新迁移）

`DevicePoint` 需新增 `MinLimit` / `MaxLimit`（nullable double），`WriteGuard.RangeValidator` 的 Range 校验需要它们。

1. 领域模型：`src/NitroGateway.Domain/Devices/DevicePoint.cs` 增加：
   ```csharp
   /// <summary>写值范围下限（null = 不限）。供 WriteGuard.Range 校验与前端录入</summary>
   public double? MinLimit { get; set; }
   /// <summary>写值范围上限（null = 不限）</summary>
   public double? MaxLimit { get; set; }
   ```
2. 新建迁移 `src/NitroGateway.Persistence/Migrations/M013_AddPointWriteRange.cs`（参考现有 M008~M012 的写法）：
   ```csharp
   [Migration(13)]
   public sealed class M013_AddPointWriteRange : Migration
   {
       public override void Up()
       {
           Alter.Table("device_points")
               .AddColumn("MinLimit").AsDouble().Nullable()
               .AddColumn("MaxLimit").AsDouble().Nullable();
       }
       public override void Down()
       {
           Delete.Column("MaxLimit").FromTable("device_points");
           Delete.Column("MinLimit").FromTable("device_points");
       }
   }
   ```
3. 同步：仓储/EF 实体/DTO 映射、前端 `types.ts` 的 `DevicePoint`、点位编辑表单。

> 注意：写值是否需要**反向缩放**（点位有 `ScaleFactor/ScaleOffset`，采集是 `工程值=原始值×ScaleFactor+ScaleOffset`）。若 UI 上写的是工程值，需先反算成原始值再调驱动，或让驱动写工程值——这是一个**设计决策点**，建议在 `WriteService` 内统一处理并加注释说明。

### 3.2 写服务 IWriteService + WriteService

建议放 `src/NitroGateway.Device` 模块（引用 Domain + Storage + Security + Protocol 依赖均可满足），或 Webapi 的 `Services/` 目录（若不想让 Device 模块依赖 Security）。

接口（骨架）：
```csharp
// src/NitroGateway.Device/Writing/IWriteService.cs
public interface IWriteService
{
    /// <summary>校验并下发单点写命令</summary>
    Task<OperationResult> WriteAsync(WriteRequest request, CancellationToken ct = default);
}
```

请求 DTO：
```csharp
public sealed record WriteRequest
{
    public required Guid DeviceId { get; init; }
    public required Guid PointId { get; init; }
    public required object Value { get; init; }   // 前端 JSON number/string
}
```

实现要点（`WriteService`）：
1. 用 `IPointManager` / 仓储查 `Device` 与 `DevicePoint`，校验点位 `Access` 允许写（`ReadWrite` / `WriteOnly`）且 `Enabled`。
2. 组装 `WriteCommand`：填充 `DeviceId / PointId / Value / DataType / DeviceStatus`（设备在线状态来源见 3.4）；`MinLimit / MaxLimit` 从点位新字段取；`PreviousValue` 从最近一次测量值取（见 3.4）。
3. 调 `_guard.Evaluate(cmd)`，失败则返回 `OperationResult.Fail(reason)`（带校验错误消息）。
4. 取驱动：`_driverPool.GetOrCreate(device)`，调 `WriteAsync(point, value, ct)`。
5. 成功后可写审计日志 / 写历史（可选，见 3.5）。

DI 注册：在 `src/NitroGateway.Device` 的服务扩展里 `AddScoped<IWriteService, WriteService>()`（若需 scope 内解析仓储）；`ProtocolDriverPool` 与 `WriteGuard` 都是 Singleton，可注入。

### 3.3 Webapi 端点

新建 `src/NitroGateway.Webapi/Controllers/WriteController.cs`（或直接加到 `DevicesController`）：
```csharp
[ApiController]
[Route("api/devices")]
[Authorize(Roles = Roles.AdminOperator)]   // Admin/Operator 可写
public sealed class WriteController : ControllerBase
{
    // POST /api/devices/{deviceId}/points/{pointId}/write
    [HttpPost("{deviceId:guid}/points/{pointId:guid}/write")]
    public async Task<IActionResult> Write(
        Guid deviceId, Guid pointId,
        [FromBody] WriteValueRequest body, CancellationToken ct)
    {
        var result = await _writeService.WriteAsync(
            new WriteRequest { DeviceId = deviceId, PointId = pointId, Value = body.Value }, ct);
        return result.Success
            ? Ok(ApiResponse<object>.Ok(new { deviceId, pointId, value = body.Value }))
            : BadRequest(ApiResponse<object>.Fail(result.Message));
    }
}
```

请求体建议统一为 `{ "value": 123 }`（JSON number/string 均可，服务层按 `DataType` 转换）。

### 3.4 WriteGuard 接线与数据来源

- **DeviceStatus（在线状态）**：Webapi 可用 `DevicesController` 已有的状态来源（设备表状态字段 / `IDeviceSnapshotCache`）；实时状态建议直接读设备当前 `State`，避免写时设备已离线仍放行。
- **PreviousValue（用于变化率校验）**：可从 `IDeviceSnapshotCache` 或 `IMeasurementStore` 查最近一次值；查不到（首次写）传 `null`，`RateLimitValidator` 会自动跳过变化率校验。
- **MinLimit / MaxLimit**：来自 3.1 新增字段。
- 失败时把 `ValidationResult.Errors` 的消息拼进 `OperationResult.Fail`，前端可直接展示。

### 3.5 错误与审计

- **统一错误**：`WriteService` 内部任何异常（驱动抛错、类型转换失败、超时）都应 catch 转 `OperationResult.Fail`，不向客户端泄漏堆栈。
- **审计**：`AuditMiddleware` 已记录所有 `/api/*` 访问（含写请求的 URL/用户/时间）；如需更强审计（写前值→写后值、谁在何时写了哪个点），可在 `WriteService` 成功后写 `write_history` 表（新增迁移）或复用告警/审计日志。
- **写失败告警**：可复用 `NitroGateway.Alarm` 的规则引擎，为“写失败”加一个事件源（可选增强）。

## 四、Web 前端实现（Vue 3 + Element Plus）

### 4.0 UI 呈现位置（Web）

核心原则：**主入口放“实时监控”页**（用户盯着实时值、就近下发上下文最清楚），**次入口放“点位管理”页**（巡检/调试）。

| 页面 | 放哪 | 说明 |
| --- | --- | --- |
| 实时监控页 `MonitoringView.vue`（主入口） | 设备卡片内每个 `point-row` 行尾加“写值”小按钮 | 对 `Access !== 'ReadOnly'` 的点位显示；点击弹 `ElDialog` + `ElInputNumber`，确认调 `writePoint()`，`ElMessage` 显示结果；卡片头部也可加“写值”下拉作快捷入口 |
| 点位列表页 `PointList.vue`（次入口） | 表格“操作”列加“写值”按钮 | 仅可写行显示（该行已有 `access` 列可判断）；适合调试单点/离线点 |
| 设备详情页 `DeviceDetailView.vue`（可选） | 点位 `el-table` 加“写值”列 | 与 PointList 场景重叠，可不做 |

通用 UI 规则：写按钮随 `Access` 显隐、输入控件随 `DataType`（Bool→开关、数值→`ElInputNumber`、String→输入框）、写成功不手动刷新（SignalR `Measurement` 推送自动更新）、对话框二次确认（文案带点位名+目标值）。

### 4.1 API 客户端

`web/src/api/devices.ts` 增加（沿用现有 `client` axios 封装，自动带 Token）：
```ts
export interface WriteResult { deviceId: string; pointId: string; value: unknown }

// 下发单点写命令
export async function writePoint(deviceId: string, pointId: string, value: unknown): Promise<boolean> {
  const { data } = await client.post<ApiResponse<WriteResult>>(
    `/devices/${deviceId}/points/${pointId}/write`, { value })
  return data.success
}
```
同时 `web/src/api/types.ts` 的 `DevicePoint` 增加 `minLimit?: number | null` / `maxLimit?: number | null`。

### 4.2 实时监控页加写按钮（最自然的入口）

`web/src/views/Monitoring/MonitoringView.vue`（卡片网格 + SignalR 实时推送）：
1. 卡片/行内对 `Access !== 'ReadOnly'` 的点位渲染“写入”按钮。
2. 点击弹 Element Plus `ElDialog` + `ElInputNumber`（按 DataType 可选开关/数值），确认后调 `writePoint()`。
3. 用 `ElMessage` 展示 `OperationResult` 的成功/失败消息（后台已把校验原因放进 Message）。
4. 写成功后本地更新卡片值，等待下一帧 SignalR `Measurement` 推送自动刷新（无需手动处理）。

> 参考既有模式：`DeviceList.vue` / `PointList.vue` 的 Element Plus 表单写法、`api/client.ts` 的 `401` 跳登录处理。

### 4.3 点位编辑表单加 Min/Max 输入

`PointList.vue` 新增点位 / 编辑点位时，为写点位提供 `minLimit` / `maxLimit` 输入框（仅 `Access` 允许写时显示）。

### 5.0 UI 呈现位置（桌面）

核心原则：**主入口放“实时数据”页**（`RealtimeView`，与 Web 对齐），**次入口放“点位管理”页**（`PointsWindow`）。

| 页面 | 放哪 | 说明 |

### 5.1 现状
- `RealtimeView.xaml` 的 DataGrid `IsReadOnly="True"`，只显示 Name/Address/DataType/Value/Quality/Time。
- `RealtimeViewModel`（`src/NitroGateway.Desktop/ViewModels/RealtimeViewModel.cs`）持有 `IDeviceSnapshotCache`、`IMeasurementStore`、`EventBridge`；`RealtimePointItem` 在文件末尾（约 L537），是 `ObservableObject`，含 `PointId/Name/Address/DataType` 与 `ValueText/QualityText/TimestampText/IsBad`，`Update(PointSnapshot)` 刷新行。

- `IProtocolDriverPool` 是 Singleton（`ProtocolServiceCollectionExtensions` 注册），桌面可直接解析。

### 5.2 实现步骤
1. **可写判断**：`RealtimePointItem` 增加 `CanWrite`（由点位 `Access != ReadOnly` 决定）。
2. **写按钮**：`RealtimeView.xaml` DataGrid 加一列“操作”，对 `CanWrite` 行渲染“写”按钮（其余行禁用/隐藏）。
3. **输入对话框**：点击弹一个简单 `Window`/`Dialog` 输入数值（可复用现有项目里的输入对话框写法，或直接仿 PointsViewModel 的编辑对话框）。
4. **VM 命令**：`RealtimeViewModel` 加 `RelayCommand WriteCommand`，在命令内：
   - 用 `_scopeFactory.CreateScope()` 解析 `IWriteService`（若服务是 Scoped）；
   - 或直接解析 `IProtocolDriverPool` 调 `WriteAsync`（跳过校验的轻量路线，见 5.3 决策）；
   - 用 `OperationResult` 弹 `MessageBox` 提示成功/失败。
5. **刷新**：写成功后可选立即 `Update(snapshot)` 或等待 EventBridge 下一帧自动刷新。

### 5.3 桌面是否走 WriteGuard（设计决策）

桌面 DI 链**未引用 Security 模块**，`AddNitroSecurity` 不在桌面注册中，因此桌面写**不能直接用 WriteGuard**。三条路线（推荐 2）：
1. 桌面项目引用 `NitroGateway.Security` 并注册 Guard → 桌面与 Web 校验一致，但桌面承担 Security 依赖。
2. **把 WriteCommand / WriteGuard / 三个 Validator 下沉到 Shared 或 Domain 层**（校验是纯逻辑，无基础设施依赖），Web 与桌面共用同一份校验逻辑 → 最干净，推荐。
3. 桌面直接调 `WriteAsync` 跳过校验 → 最快，但写值范围/变化率无保护，现场风险高。

## 八、后续可选增强

- **写后读回确认**：`WriteAsync` 成功后延迟读回该点，比对写入值，失败则标记写失败并可选告警。
- **批量写**：`WriteBatchAsync` 已实现，可在 Web/桌面提供多选点位批量下发；注意当前实现是逐条循环、一条失败即整体失败，UI 需展示逐点结果。
- **写命令队列 / 定时写**：把写命令放入队列（参考 `Forwarder` 的 Outbox 思路）实现顺序下发与离线补偿。
- **写历史表**：`write_history`（device_id, point_id, value, operator, request_time, result）配合审计中间件形成完整写留痕。
- **写权限细化**：按点位/设备粒度区分 Operator 可写集合（当前 RBAC 只有角色级）。
