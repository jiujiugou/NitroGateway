## 1. 一句话讲清项目（30 秒电梯版）

> "一个 .NET 10 的工业物联网边缘网关：用 Modbus TCP/RTU、S7、OPC UA 三套协议采 PLC 数据，本地 SQLite 落时序 + 转发缓冲（断点续传），再经 MQTT QoS1 发布上云；Vue3 Web 端做配置/实时监控，WPF 桌面端做现场上位机；断网不丢数、采集挂了自愈、云端恢复不冲垮，726 个单测 + Docker Compose 部署。"

## 2. 全链路（3 分钟版，讲的时候按这条线走）

```
[现场设备] PLC(Modbus TCP/RTU、S7、OPC UA)
   │  经 Protocol 复合工厂按设备类型建驱动（Protocols + OpcUaRegistration）
   ▼
[采集] CollectionEngine(1s 周期, 后台服务)
   → DeviceReader.GetDuePoints(点位级 ScanIntervalMs 降频, ADR-062)
   → 驱动读 → PointValuePipeline(类型转换→工程缩放→死区过滤 ChangeDetector)
   → DataDispatcher 双写(SinkDispatcher):
        ├─ SQLite 时序库(MeasurementStore)        ← 本地留档
        └─ ForwardBuffer(FIFO, 两阶段提交, InFlight 防重) ← 断网也先落库
   ▼
[转发] ForwarderEngine(5s 周期)
   → Forwarder(Dequeue → JSON → MQTT Publish QoS1 → 成功才 Commit/删；固定批量上限 ≤1000)
        └─ 失败 → retry_count+1 → ≥5 → 直接 DELETE 丢弃(上报 dropped 指标, 2026-08-22 删死信)
        └─ 批量失败 → 保留重试, 不节流(2026-08-22 删 AIMD)
   ▼
[云端/中心] MQTT Broker(mosquitto) → Ingest 中心端汇聚(B 方案, ADR-025/034/035)
[双端 UI]  Webapi: REST + SignalR(/hubs/live, OutboxConsumer 推实时) + HealthChecks + 审计
           Desktop: WPF MVVM, 本地 SQLite + 与网关 SiteConfigSync 双向同步(ADR-036/046), 实时页四层缓冲(ADR-050)
```

一句话记牢：**采集与转发解耦**（先落库再发，转发失败不影响采集）；**熔断与健康互不控制**（CB 是门控"能不能连"，HM 是判定"值不值得信任"）。

## 5. 三个必练系统故事（按"问题→定位→修法→测试"讲，能报 726 单测）

1. **断网数据怎么不丢**：采集先双写落 ForwardBuffer（SQLite）→ 转发只在 MQTT 确认后 Commit；断网重连自动续传；反复失败重试超限丢弃不堵（ADR-001）
2. **采集挂了怎么自愈**：每设备独立熔断器 5 连败 Open → 30s 半开探测 → 冷却翻倍；健康监控 3 连败判定离线、恢复自动上线并重置熔断（ADR-016）
3. **云端恢复怎么不冲垮**：每轮固定取 ≤1000 批排水（不会瞬间冲垮）；MQTT 总开关可运行期启停（2026-08-22 删 AIMD；ADR-059）
