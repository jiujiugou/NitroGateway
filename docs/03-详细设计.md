# 03 详细设计（NitroGateway）

> 版本：v1.0 ｜ 日期：2026-08-30 ｜ 依据：代码现状（src/ 各模块）+ 配置 + 迁移清单

## 1. Domain 领域模型

| 类型 | 说明 |
| --- | --- |
| Device | 设备：协议标识、Endpoint、UnitId、串口参数、站点、健康状态 |
| DevicePoint | 点位：地址、数据类型、缩放、死区、ScanIntervalMs、读写权限（PointAccess） |
| PointSnapshot | 单次采集快照（携带 PointName、Access，供上行与告警） |
| MeasurementRecord | 测点记录：值、数据类型、Access、Timestamp、ReceivedAt、QualityCode |
| BatchMeasurements | 一轮采集批次：SiteId、V(=1)、Id、DeviceId、扫描起止、Records |
| RawPointValue | 协议原始值边界（含字节序/缩放前） |
| IProtocolDriver / DriverCapability / DriverState | 协议驱动抽象与能力声明 |
| QualityCode | Good / Bad / Uncertain 数据质量 |
| PointAccess | ReadOnly=0 / WriteOnly=1 / ReadWrite=2 |

## 2. Collection 采集引擎

### 2.1 组件

| 类 | 职责 |
| --- | --- |
| CollectionEngine | BackgroundService + PeriodicTimer，1s 周期调度；异常循环内捕获 + 5s 重试，不整机退出 |
| DeviceCollector / IDeviceCollector | 单设备一轮采集编排 |
| DeviceReader / IDeviceReader | 读原始值，3 次重试 + 指数退避 |
| PointValuePipeline / IPointValuePipeline | 类型转换、工程缩放（Scale/Offset）、死区过滤、点位级降频（ScanIntervalMs 三态判定） |
| DataDispatcher / IDataDispatcher | 双写：SQLite MeasurementStore + ForwardOutbox |
| MeasurementWriteHost | 存储写入异常隔离（LogError + 跳过本批继续消费，OCE 除外） |
| SinkDispatcher | 多 sink 分发 |
| CircuitBreaker / CircuitBreakerRegistry | 每设备熔断状态机（Closed/Open/HalfOpen），线程安全 |
| HealthReporter | 采集健康上报 |

### 2.2 熔断状态机

```
Closed ──连续5次失败──→ Open ──冷却30s──→ HalfOpen ──探测成功──→ Closed
                          │                    └──探测失败──→ Open (冷却×2,上限5min)
                          │
                     拒绝所有采集请求
```

### 2.3 健康监控（DeviceHealthMonitor，单一权威来源 SST）

```
HealthMonitor
    │ 计数 成功/失败 → 判定 Online/Offline 迁移
    ├── PersistenceListener          → 写数据库
    ├── CircuitBreakerHealthListener → Online 时重置熔断器
    └── SignalRDispatcher            → 推前端 (DeviceStatusChanged)
```

- 3 次连续失败 → Offline，3 次连续成功 → Online；初始 Unknown 可自动转 Online。
- 熔断器（门控：能不能连）与健康监控（判定：值不值得信任）互不控制。

## 3. Forwarder 转发引擎

### 3.1 组件

| 类 | 职责 |
| --- | --- |
| ForwarderEngine | 5s 周期 + 首轮立即执行；积压告警、磁盘 Critical 跳过、停机 drain |
| Forwarder | Dequeue → Serialize → MQTT Publish(QoS1) → Commit |
| JsonMessageSerializer | BatchMeasurements → camelCase JSON（UTF-8） |
| HttpForwarderEngine | HTTP 北向通道（Channels=http/both） |
| IMessageSerializer / IForwarder | 可替换接口 |

### 3.2 两阶段提交（Forward Outbox）

- `forward_outbox` 表：Pending → InFlight → Commit(删除) 或 MarkFailed(retry+1)。
- retry_count ≥ 5 → DeadLetter（不再 Dequeue）。
- 单批失败不阻塞后续；Commit/MarkFailed 失败记 Error 防静默丢数。
- 停机 drain：等待采集侧停止（≤15s）后，MQTT 连接期内限时（≤10s）排空缓冲。

### 3.3 限流（2026-08-22 起固定上限，替代 AIMD）

- 单次出队 ≤ 1000 批（MaxDequeuePerCall）；单轮排水 ≤ 2000 批（MaxDrainPerRound）。
- 积压 > 1000 批告警（首超立即、之后每 60s，回落后重置）。
- 历史 AIMD（失败减半/Delay +20ms、成功 +10/-5ms）已简化，代码不再存在 ForwardingThrottle。

## 4. Command 命令回写（ADR-069）

### 4.1 契约

| 项 | 值 |
| --- | --- |
| 订阅 topic | `nitrogateway/+/+/commands`（QoS1，由 CommandHostedService 订阅一次，wrapper 重连自动重放） |
| 命令载荷 | `{commandId, type:"WritePoint", pointId, value, requestedAt}`（camelCase） |
| 回执 topic | `nitrogateway/{siteId}/{deviceId}/commands/ack`（QoS1） |
| 回执载荷 | `{commandId, result: "Success"/"Failure", error, at}` |

### 4.2 处理流程

```
CommandHostedService（单消费者，消息按序）
  → CommandRequestParser.Parse（topic 4 段校验 + siteId 一致 + JSON 校验）
  → CommandProcessor.ProcessAsync
      ├─ 幂等：commandId 缓存（ConcurrentDictionary ≤1024，超出清一半）
      ├─ 首次 → IWriteService.WriteAsync（WriteGuard 校验 → 写 PLC）
      ├─ 缓存回执 + 发布 ack（发布失败仅记日志，云侧重试幂等兜底）
```

- 写值异常隔离为 Failure 回执，不中断消费循环。
- 指标：`nitro_command_processed_total{result}`、`nitro_command_ack_publish_failures_total`。

## 5. Alarm 告警引擎

### 5.1 评估

```
PointSnapshot → AlarmEvaluator → 查规则 → 阈值比较 → Duration 判定 → Alarm
```

- 阈值操作符：`>` `>=` `<` `<=` `==` `!=` `Between`。
- Duration 去抖：值持续超限 N 秒才触发，中间回落重置计时。
- 去重：Active 期间不重复生成新告警。

### 5.2 生命周期

```
Pending → Active → Acknowledged → Resolved
```

### 5.3 通知

- `IAlarmNotifier` 可插拔；默认 `MqttAlarmNotifier` 推送 MQTT（钉钉/企微/邮件可扩展）。
- 规则缓存：AlarmRuleCache + CachedAlarmRuleRepository。

- SQLite PRAGMA（SqlitePragmas）：WAL 等优化。
