## 修复: Dockerfile center 镜像构建失败（2026-08-17）

- 现象: 服务器 `docker compose -f docker-compose.center.yml up -d --build` 失败，
  `RUN dotnet restore "$APP_PROJECT"` 报 MSB3202——容器内缺
  `src/NitroGateway.Desktop`、`src/NitroGateway.Storage/Disk`、两个 tests 的 csproj [NitroGateway.slnx]。
- 根因 1（Docker ARG 作用域）: `ARG APP_PROJECT` 声明在 `FROM` 之前（全局作用域），build 阶段内不可见；
  未在阶段内重新声明，`$APP_PROJECT` 为空 → `dotnet restore ""` 回退还原工作目录的 NitroGateway.slnx，
  而容器只拷了部分 csproj → MSB3202。
- 根因 2（隐藏缺陷，修完 1 才暴露）: `NitroGateway.Storage.Disk` 被 Persistence/Collection/Forwarder/Webapi
  硬引用，但 restore 前的 COPY 集不含它的 csproj → restore 跳过它 → publish `--no-restore`
  缺 project.assets.json 报 NETSDK1004。说明该镜像此前从未真正构建成功（原始 Dockerfile 同样有此缺陷）。
- 修复（仅 Dockerfile，未动代码/依赖）:
  - `FROM ... AS build` 后补 `ARG APP_PROJECT` 重新声明，进入阶段作用域（与 CI build-server 按项目 restore 一致）。
  - COPY 集补 `src/NitroGateway.Storage/Disk/*.csproj`。
- 验证（红绿对照，临时目录模拟 Dockerfile restore → COPY src → publish 全流程）:
  - 红: `dotnet restore ""`（空 APP_PROJECT）复现 MSB3202，与服务器报错一致。
  - 绿: restore + publish Ingest（compose 入口）与 Webapi（默认入口）均成功（exit 0）。
  - `dotnet build NitroGateway.slnx` 0 错误（35 警告均为既有）。
- 服务器操作: 同步 Dockerfile 修改（git pull 或手动替换）后重跑
  `docker compose -f docker-compose.center.yml up -d --build` 即可。提交/推送由用户执行。
