## 修复：CollectionEngine 关闭期 ODE 逃逸（2026-08-12）
- 问题：停止宿主时 PeriodicTimer.WaitForNextTickAsync 因停止令牌取消抛 OperationCanceledException（CollectionEngine.ExecuteAsync 的 while 条件，原第 58 行），且 while 等待在 try 之外，ODE 逃逸出 ExecuteAsync（ExecuteTask 以 Canceled 结束）。宿主 TryExecuteBackgroundServiceAsync 会静默吞并（不崩溃、不记错误日志），但调试器会显示 first-chance 异常，关闭路径不干净。

- 测试：新增 CollectionEngineShutdownTests.StopWhileWaitingForNextTick_ExecuteTaskCompletesSuccessfully，红（canceled=True）到绿（成功完成）；dotnet build NitroGateway.slnx 0 错误；单测 437 例中 436 通过，DesktopViewSmokeTests 2 例为已知 WPF 渲染 flaky（见 2026-08-11），与本次无关。

## 决策: 架构角色分离——桌面端采集、Web 平台管理（2026-08-12，用户拍板）
- 背景: 产品开始出现错乱——中心 Webapi 误跑采集/转发（ADR-034）、桌面与中心配置各写各的（ADR-033）、上行 topic 无 site 维度；对照大众设计（ThingsBoard Edge / Azure IoT Edge / EMQX 边缘）定位为角色混淆
- 结论: 桌面端=边缘采集角色（采集/本地缓存/断网续传/上行转发，现场 UI 以桌面端为准）；Web=平台管理角色（设备管理/数据展示/告警，中心不采集不转发）；中心库数据写点唯一=ingest
- 路线: 第 0 步 Deployment:Mode 裁剪中心模块（止血）→ 第 1 步上行 topic 加 siteId 契约 → 第 2 步 ADR-033 阶段 3/4 配置同步 → 第 3 步可选物理拆分（边缘 Agent 独立进程）
- 产出: notes/ADR/ADR-035-architecture-edge-center-role-split.md（含待定项：siteId 落地时机建议与第 2 步同做）
