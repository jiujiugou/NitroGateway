## 实施: ADR-053 三处瘦身——死区变化抑制 + 心跳兜底（2026-08-16，AI 代执行）
- 背景: 用户确认「DB 落库 + MQTT 转发 + SignalR 推送三处一起瘦身」。1s 全量快照 10 设备约 600 点
  ≈ 5184 万行/天、30 天 ~15 亿行、本地盘 ~310GB 会撑爆，且 SignalR 每秒全量 600 条加重 Web 负担。
  用户已确认：桌面实时图数据在内存（EventBridge 帧），死区抑制不影响桌面实时图。
- 设计（先写文档再做，ADR-053 已拍板）: 抑制点不在 Pipeline，在 `DataDispatcher.DispatchAsync`
  内统一计算一次「放行子集」，存储(SQLite)/转发(MQTT)/推送(SignalR) 三处共用；事件仍发全量
  （桌面实时图/告警不受影响），`PersistedSnapshots` 携带实际放行子集。
- 改动（C#）:
  - `PointSnapshot` 新增 `Deadband`（默认 0，只增不改）；`PointValuePipeline` 四处 `new PointSnapshot`
    均透传 `point.Deadband`（管线不丢数据语义不变，抑制在 Dispatcher 层，类注释同步澄清）。
  - 新增 `ChangeDetector`（`src/NitroGateway.Collection/Pipeline/ChangeDetector.cs`）：纯类，
    维护每点 lastValue/lastRawValue/lastQuality/lastStoredAt；`Filter` 规则——首样本必写 /
    质量变化必写 / 心跳超时必写（默认 300s）/ Bool·String 值相等才写 / 数值 `|Δ|<Deadband` 抑制、
    `≥` 放行（恰好等于视为变化）/ Deadband=0 全写 / 数值无法转 double 保守放行。
  - `PointStoredEvent` 新增 `PersistedSnapshots`（null=未启用抑制，回退全量）。
  - `DataDispatcher`：构造新增可选 `ChangeDetector`（兼容现有测试）；`toStore` 计算一次，
    `toStore.Count>0` 才 Post + 入缓冲；事件永远全量 + PersistedSnapshots=toStore。
  - `DeviceStatusDispatcher`（SignalR）：改用 `e.PersistedSnapshots ?? e.Snapshots`，空列表直接 return。
  - `Collection:DeadbandHeartbeatMs=300000` 新配置（Webapi/Desktop appsettings 同步），注册
    ChangeDetector singleton，`>0` 校验。
- 改动（前端）:
  - `MonitoringView.vue`：snapshots 加 `lastSeenAt`；stale 改「超 2×心跳=600s 未收到更新才灰」
    （30s tick 强制刷新响应式，onUnmounted 清理）。
  - `HistoryView.vue`：曲线 `smooth:true` → `step:'end'`（稀疏变化点不画假连续线）。
- 测试: 新增 `ChangeDetectorTests` 12 个 Fact（首样本/死区内抑制/恰好等于放行/超死区/Deadband=0
  全写/质量变化/心跳超时/新实例重启/ Bool·String/非数值保守放行/构造非正拒绝）；
  `DataDispatcherTests` 新增 3 个（三处共用放行子集、全抑制时不写库不入缓冲但事件仍发全量且
  PersistedSnapshots 空、无 ChangeDetector 时全量透传回归）——FakeStore 加 Written 捕获、
  FakeSink 用 unbounded Channel + 计数捕获事件。
