## Telemetry 追踪 File 导出器（ADR-057，2026-08-19）

用户反馈：ADR-056 之后"追踪在哪里观察？日志里没看出来"。根因：默认 `Exporter=Otlp` 走 localhost:4317 collector，本机无 collector 时 span 被丢弃，且 Otlp 不写 Serilog .log 文件 → 需要"无需 collector、可直接落盘"的观察方式。

改动：
- 新增 `Tracing/FileActivityExporter.cs`（`BaseExporter<Activity>`）：span 以 JSON Lines 追加写 `{LogDirectory}/traces-yyyyMMdd.jsonl`（本地日期滚动）；字段 ts/duration_ms/name/kind/trace_id/span_id/parent_span_id/status/service/tags；线程安全 + 跨日 Flush 切换 + Dispose 冲刷。
- `TelemetryTracingOptions`：`TracingExporterKind` 加 `File=3`；新增 `LogDirectory`（默认 `logs/traces`，环境变量 `Telemetry__Tracing__LogDirectory` 可覆盖）；`Resolve` 同步解析。
- `AddNitroTelemetry(IConfiguration,...)`：`Exporter=File` 分支挂 `SimpleActivityExportProcessor(FileActivityExporter)`；XML 注释同步。
- File 导出器独立于 Serilog：span 写 `logs/traces/`，不混入 `logs/nitrogateway-.log`；`logs/` 已在 .gitignore。

验证：
- `dotnet build src/NitroGateway.Telemetry` 0 错误 0 警告；Telemetry 过滤器测试 14 通过（新增 File 写盘测试）；全量（重定向输出 + `--filter !~DesktopThemeTests`）**633 通过 / 0 失败**。
- 冒烟（`Telemetry__Tracing__Exporter=File` + 临时 LogDirectory + 带设备 DB + `ASPNETCORE_ENVIRONMENT=Development` 启动 Webapi，端口 5199 避开运行实例 5100）：20s 写出 `traces-20260819.jsonl`，**50 条 span 覆盖全部 8 个名字**（CollectRound/CollectDevice/ReadDevice/Pipeline/Dispatch/Forward/SqliteWrite/MqttPublish），含 trace_id/parent_span_id/service/tags。冒烟临时目录已清理；未停运行中的 Webapi 实例（PID 47884）。
- 复检注意：运行实例锁 `bin/Debug`，构建/测试一律重定向输出；临时测试输出目录的 appsettings.json 是 Ingest 的 copy-conflict 胜者，冒烟时用 Webapi 源 appsettings.json 覆盖。

## Docker 部署验证（2026-08-19）
用户问「现在这个 docker 部署文件能使用吗」。真实验证（非仅 `docker compose config`）：build + up + 健康检查 + 登录 E2E。
发现并修复 3 处部署缺陷：
1. compose 只强制覆盖 admin 密码，operator/viewer 仍默认测试密码 → 生产校验拒启崩溃循环。修复：`docker-compose.yml` / `docker-compose.center.yml` / `.env.example` 新增必填 `OPERATOR_PASSWORD` / `VIEWER_PASSWORD`（`Security__Users__1/2__Password`）。
2. Kestrel 容器内监听 127.0.0.1 而非 0.0.0.0（`appsettings.json` `Urls=localhost:5100` 压过 Dockerfile 的 `ENV ASPNETCORE_URLS`）。修复：appsettings `Urls` 改 `http://0.0.0.0:5100`。
3. compose/.env 以明文覆盖密码，而代码只认 PasswordHasher 哈希 → 登录 500（`FormatException: not a valid Base-64 string`，`TokenGenerator.IssueToken`→`VerifyHashedPassword`）。修复：`AddNitroSecurity` 配置加载阶段明文归一化（`IsHashedPassword` 按版本字节判定，非哈希一律按明文；生产先拒绝默认测试密码再 `HashPassword` 写回 jwtConfig，TokenGenerator 不变）。
验证：`dotnet build` 0 错；全量单测 **645/645**（新增 3：生产明文默认密码拒启 / 生产明文强密码启动且哈希归一化 / 开发明文不拒）；容器 E2E：healthz/readyz 200、`nitro_mqtt_state=2`、admin/operator/viewer 明文登录 200、token 调 `GET /api/devices` 200、经 web 5170 代理登录 200。
注意：本机 1883 被开发 mosquitto 占用，验证用临时 override 改 1884（`docker-compose.verify.yml` 已删，勿提交）；干净机器直接 `docker compose up -d` 即可。本次改动未提交，git 提交默认留给用户。
