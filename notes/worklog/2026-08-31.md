## 验证：NitroGateway Modbus RTU 驱动设计（对用户模拟器端到端）

### 三问
- 为什么做：用户想确认 `src/NitroGateway.Protocol/Modbus/ModbusRtuDriver.cs` 的设计正确性，且可用自己的模拟器验证。
- 验收标准：用 `RtuSlavePanel` 同一从站实现（`ModbusRtuSlaveServer` + `SlaveDataStore`）跑通网关驱动全部功能码/DataType/异常场景，全部绿。
- 不做会怎样：驱动正确性只靠单测推断，缺少真实串口线路的端到端证据。

### 验证工具（新建，位于模拟器仓库，未入 NitroGateway 仓库）
- `D:\resource\Modbus.project\_verify\gw-rtu-verify\`（csproj + Program.cs）
- 拓扑：模拟器从站 `ModbusRtuSlaveServer` → COM1；网关 `ModbusRtuDriver` → COM2（ELTIMA 虚拟串口对，115200/None/8/One/ABCD），与既有 RtuSlaveTest 同对。
- 运行：`dotnet run --project D:\resource\Modbus.project\_verify\gw-rtu-verify`

### 验证结论：设计正确，37/37 PASS
- 功能码全覆盖：FC01/02/03/04 读，FC05/06 写单，FC10 写多寄存器（Int32/Int64/UInt64/Float/Double/String）。
- DataType 全回环 + ABCD 大端：Int16/UInt16/Int32/UInt32/Int64/UInt64/Float/Double/Bool/String 读写回环一致；
  UInt64 用 4 字非平凡值 0x1122334455667788 严格验证 ABCD 重组，Int64 验证 MinValue+2 符号位。
- 批量读合并：3 个连续 Int16 合并一次 FC03；Float+Int16 紧邻跨类型分段；Coil 独立 Range，全部返回正确。
- 同端口多从站：UnitId=1/2 共享 COM2（租约数=2），站号切换后各自读回正确。
- 异常场景：未知从站 UnitId=9 超时优雅失败（Time out:1500）；越界地址 EXC2 优雅失败；写后 Regenerate 不被随机覆盖。
- 停止/断开优雅：`server.Stop()` 后 IsRunning=false。

### 过程中排除的“假故障”（均为验证工具侧，非驱动 bug，不记 ADR）
1. UInt64 读“不一致”：模拟器 `SlaveDataStore.WriteType` 入参是 `double`，>2^53 播种会丢精度；改直接写 4 个寄存器字后严格一致 → 证明驱动 UInt64 ABCD 重组无误。
2. FC10 写后读回 null：写入偏移 ≥100 超出从站 Holding 数组（由 PointDef 决定，最小 100）；加 H_pad@200 扩大存储后全绿。
3. 批量读 Coil 期望错：`Coil[0]=0x01` 只置 bit0，batch 的 `b_c@00004`(offset3) 应为 false；改 `0x09` 后一致。

## 结论：OPC UA 放在与 Modbus 相同的“设置位置”（设计评审）
- 结论：把 OPC UA 配置放进与 Modbus 相同的设置位置（共用 DeviceConnection + Parameters 字典 + 同一设备表单）结构上没问题，与“协议特有参数走 Parameters”的统一设计一致。
- 注意点（非“位置”本身的问题，而是 OPC UA 特有维度当前缺入口）：
  1. OpcUaDriver 目前不读 Parameters：身份硬编码匿名（new UserIdentity()），选端点 useSecurity=_hasAppCertificate、失败回退 None → 服务器要求用户名/密码或加密端点时连不上，缺安全策略/认证参数。
  2. 若日后往 Parameters 加 UserName/Password：明文存 ConnectionParams(SQLite JSON) 且随配置同步到中心有泄露风险（Modbus/S7 无机密，同位置没问题）。
  3. 证书校验 AutoAcceptUntrustedCertificates=true 是演示/内网妥协，生产改信任库白名单。
  4. 加 OPC UA 特有参数时沿用 PascalCase key + 驱动内解析/默认/校验（对齐 Modbus Parse*），UI 同步补字段。
- 补充：确认 `src/NitroGateway.Protocol/OpcUa` 放置正确（并列 Modbus/S7，已入 slnx，Protocols.csproj 引用 + OpcUaRegistration 注册）。
- 修复：AGENTS.md 第 34 行雷区过时——`Protocol.OpcUa` 已在 4714d46 并入 slnx 并启用，从“未入 slnx”清单移除（未提交，留待用户提交）。
