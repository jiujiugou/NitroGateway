# specs/ 特性目录（每个待办一个目录, 四件套）

- 每个待办对应目录 `notes/specs/NNN-标题/`, 内含四份文件:
  - `spec.md` — 做什么/为什么: 背景与需求三问、目标、边界、验收标准、工程基线。用户确认对象。
  - `plan.md` — 怎么做: 现状代码位置、方案、风险与对策、假设、确认状态。用户确认对象。
  - `tasks.md` — 执行清单: 前置、任务分解、执行记录、验收勾选。处理待办 = 推进此文件。
  - `验收指标.md` — 收尾对照: 自动验收 + 行为指标 + 运行时验证 + 基线勾选; tasks 全勾选后生成, 用户最终验收依据。
- 模板: `notes/templates/{spec,plan,tasks,验收指标}.md`, 只在生成时读一次; 各文件控制在一屏内。
- 流程: backlog 登记 → spec 按闸门确认 → plan 按闸门确认 → tasks → 执行 → 生成并勾选验收指标.md → 用户最终验收 → 回写 backlog [x]。
- 确认: 对象是 spec/plan 末尾决策点（≤3 个问题）, 不是全文; 闸门分级 G1/G2/G3 见 AGENTS.md。
- 交互: 对话驱动——用户只定方向/拍板决策点/最终验收, 不要求阅读或维护本目录; 文档与执行记录由 AI 维护, 用户点名才展示。
- 状态: 推迟项在 spec.md 标注触发条件; 已完成项默认不进上下文, 用户点名才读。
