# 并发建模方法（①–⑦）

> 并发分析的核心是**顺序即分析顺序**，每一步都要有推理链，不要直接甩结论表格。
> 只用于真正有共享生命周期资源的子系统，不要当通用流程套。

## ① 定义系统行为

先于一切。不定义"应该怎样"，后面所有不变量都没有基准。

- 目的 / 契约（前置·行为·返回·副作用）/ 生命周期 / 正常异常流 / 调用方义务。
- 关键问：返回的引用/句柄**有没有租约，还是裸借用**？谁负责"使用期"？
- 系统在并发下**必须保持不变**的行为是哪些？

> 多数并发缺陷的种子在这里：接口没回答"谁负责使用期"，所有权必然断裂。①挑出来后，②–⑤都是它的推论。

## ② 识别共享资源

从①倒推：哪些状态被多个执行流访问且需一致？

- 分类：可变状态 / 非线程安全外部对象 / OS 句柄 / 队列 / 持久化状态 / 逻辑资源。
- 找出**复合操作（check-then-act）**——头号缺陷形状。

## ③ 定义并发边界

对每个操作列出**所有到达路径**，再判断哪些真会时间重叠。

- 上下文：采集定时器 / 请求线程 / 协议回调 / 后台服务 / 健康监控 / 关停 / 取消。
- 重点抓**因果相关但线程分离**：A 触发事件 → 另一线程回调 → 动 A 刚用的资源（如 fire-and-forget 健康回调）。

## ④ 定义所有权

- 独占/共享、粒度、**生命周期 vs 使用期**、唯一访问入口。
- 标出**借出处的所有权断裂**，分析加租约的成本 vs 接受边界。

## ⑤ 定义不变量 / 状态转换

- 状态机三件套：状态集 / 允许迁移 / 终态。
- 四类不变式：状态 / 迁移 / 终态 / 进展。
- 每条要有**违反检测器**（否则无法裁判）。
- 显式写出**不承诺的边界（豁免）**——往往比不变量更重要。

## ⑥ 定义同步规则

互斥 / 锁序 / 可见性 / 取消传播 / 顺序阻塞策略。
写清哪些动作留临界区（保原子）、哪些移锁外（慢 I/O），及理由。

## ⑦ 选择实现机制

`lock` / `Interlocked` / `SemaphoreSlim` / `Channel` / `Lazy` / 不可变快照 / Actor。
优先**结构强制**而非"约定+自觉"：新增方法时"想绕都绕不过"才算数。
