# ADR-068：VS Code 端口转发占用 127.0.0.1:5100，web 连不上本地后端

## 问题
web（`npm run dev`，5173）代理 `/api/*`、`/hubs/*` 到 `127.0.0.1:5100` 超时/无响应，
登录与 SignalR 全部连不上；但后端 `NitroGateway.Webapi` 明明在跑（`dotnet run`）。

## 根因 / 代码位置
- 本地后端绑 `0.0.0.0:5100`（`src/NitroGateway.Webapi/appsettings.json` 的 `Urls`），在局域网 IP 上可访问。
- VS Code「端口转发」机制（某个窗口下的 NodeService 子进程）占用 `127.0.0.1:5100`，
  成为比 `0.0.0.0` 更精确的绑定 → 本机访问 `127.0.0.1:5100` 全部被它劫持；
  该转发目标无响应 → TCP 能连上但一字节不返回（curl 超时）。
- 实测：杀掉该 NodeService 后 VS Code 立即重建绑定（是运行时转发，杀进程无效）；
  转发未持久化在工作区 state 里，**重启对应 VS Code 窗口即可清掉**。
- 受影响代码：`web/vite.config.ts`（ADR-063 定的 `127.0.0.1` 目标正好撞上）。

## 修复方向（已完成）
- `web/vite.config.ts` 代理 target 由 `127.0.0.1:5100` 改为 `127.0.0.2:5100`：
  后端绑 `0.0.0.0`，`127.0.0.2`（同属 127.0.0.0/8 回环）同样可达（实测 `/healthz` 200），
  绕开 VS Code 对 `127.0.0.1` 的占用；`/hubs` 的 ws 同步改。
- 仅 dev 代理配置，不影响生产（生产走 nginx `/api/` 反代）。
- 治本：在占用 5100 的 VS Code 窗口「端口」面板停止该转发，或重启该窗口。
