# Acceptance Criteria — Agent 执行规范

> 面向执行 Agent。编写时遵循「生成规则」，验收时遵循「执行规则」。

## 1. 生成 AC

* 路径：`notes/AcceptanceCriteria/AC-<主题>.md`
* 文件头包含：**范围、ADR 引用、不在本次范围**。
* 每条 AC 必须可判定 `PASS / FAIL`，并提供可复现证据，三选一：

  * 可执行测试名；
  * API 请求 + 期望状态码/字段；
  * `文件:行号` + 源码特征（标注「仅源码检查」）。
* 验证方式必须包含：**动作 + 期望结果**。
* 末尾提供 `V-*` 验证命令：每条均为**可执行命令 + 期望输出**。
* 禁止写实现过程、技术决策、工作日志。

## 2. 执行 AC

按顺序执行：

1. 通读范围与全部条件。
2. 依次执行 `V-*`，记录真实输出。
3. 逐条判定 `PASS / FAIL`，附可复现证据。
4. 核对范围外未被修改、未被冒充为完成。
5. 输出验收报告：`PASS/FAIL + 证据 + 汇总`。
6. **只读不改。**

## 3. 硬约束

* 禁止只打勾、不取证。
* 禁止修改代码/测试以凑 `PASS`。
* 本次新增测试不得作为唯一验收证据。
* 「源码看起来实现了」≠「行为已验证」；UI 仅源码检查必须明确标注。
* **无证据不得判 `PASS`。**

## 4. 完成定义

仅当：

```text
全部 AC = PASS
+ 证据完整
+ 范围外无越界
+ 无未解决阻塞
```

满足后**立即停止，不扩大改动**。
